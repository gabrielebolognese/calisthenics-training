# Build my calisthenics training app (personal PWA for iPhone)

You are building a small, personal web app that runs my calisthenics plan on my iPhone. I add it to the home screen from Safari and use it as a standalone app. It is NOT a general-purpose fitness app. It has one user (me), one plan (mine), no accounts, no backend, no analytics.

The app's only job: tell me, in the easiest way possible, exactly what to do right now. "Hold this for 8 s." "Rest 90 s." "Do 6 reps." "This week is test week, today you test the push skills." It times everything, logs everything, and computes the next session from my logs using the plan's progression rules.

## 0. Source of truth

- The training plan document is in this folder (an export of "Calisthenics Strength Plan"). Read ALL of it before writing any code.
- The document is the source of truth for exercises, sets, reps, holds, rest times, rep standards, progression rules, the 24-week block structure, deloads, tests, abs, GTG and recovery rules.
- This prompt adds app behavior and fills gaps the document leaves open for software (exact numbers the doc does not give, edge cases). If this prompt and the document disagree on training content, the document wins.
- Every gap you fill yourself goes in `DECISIONS.md` (one line each: what was ambiguous, what you chose, why). Do not silently invent training content.

## 1. Workflow (do it in this order)

1. **Spec first.** Read the doc, then write `PLAN_SPEC.md`: a structured extraction of every session, every exercise (name, cue, rep standard), every progression rule, the block/week/day structure and the test protocol. Write `DECISIONS.md` alongside it. Stop and show me both before writing app code.
2. **Plan data + engine + tests.** Encode the plan as typed data and build the progression and cycle engine as pure functions, with unit tests.
3. **Session player.** Timers, audio and voice cues, wake lock, resume after reload.
4. **Today, Log, Progress, Settings screens.**
5. **PWA + deploy.** Offline support, home screen install, deploy to an HTTPS host.

Commit after each milestone. Keep dependencies minimal.

## 2. Tech stack

- Vite + React + TypeScript (strict).
- IndexedDB through Dexie for all data. Call `navigator.storage.persist()` on first launch.
- `vite-plugin-pwa` for the service worker and manifest (offline-first, auto update).
- Plain CSS (CSS variables). No UI library. Charts are hand-drawn SVG, no chart library.
- Vitest for the engine tests.
- Hosting: static site on GitHub Pages (via GitHub Actions) or Cloudflare Pages. It MUST be HTTPS: the Wake Lock API and the service worker only work in a secure context. Configure the Vite `base` path correctly for the host.

## 4. Plan model

Encode the plan as data, not as hardcoded screens.

- **Exercise:** `id`, `name`, `cue` (the short note from the session tables, for example "Straight extended arm"), `standard` (the rep standard text from Core rules), `type` (reps | hold | perSideReps | perLegHold | emom | practice), optional `weighted`.
- **Session template:** Day 1 to Day 7 (Push A, Pull A, Off, Push B, Pull B, Skill, Off), an ordered list of exercise slots, each with its progression rule and rest time.
- **Step** (what the player renders, generated by the engine for a specific day):
  - `warmup`: list of `{ name, seconds }` items, auto-advancing.
  - `hold`: exercise, target seconds, set index/total, side or leg label if alternating, rest after.
  - `reps`: exercise, reps (or reps per side), load (for example "+5 kg"), target RIR, set index/total, rest after.
  - `emom`: exercise, rounds, reps per round, interval seconds (60 for EMOM, 120 for doubles every 2 min).
  - `totalReps`: exercise, target total, RIR, rest between sets.
  - `maxHold`: stopwatch, for tests and the weekly handstand max.
  - `amrap`: rep count entry, for tests.
  - `practice`: free practice for N minutes or N attempts (handstand practice, flag on straight bar).
  - `attempts`: N attempts with success yes/no (no-transition muscle-up).
  - `rest`: seconds, plus a preview of the next step.

## 5. Cycle engine (which day is today)

- The plan runs by **day numbers 1 to 7, not weekdays**. Position = block (1 to 3), week (1 to 8 inside the block, 1 to 24 overall), day (1 to 7).
- **Today = the next uncompleted cycle day.** A training day is completed by finishing its session (or "Finish early", which saves what was done).
- **Never double up:** at most one cycle day can be completed per calendar date (local time, Europe/Berlin). A missed training day does not get skipped, the cycle just waits for it.
- **Off days (Day 3, Day 7)** complete automatically when the calendar date ends on the day they became due. Example: Day 2 done on Monday, Tuesday shows Day 3 (rest), Wednesday shows Day 4. If I miss Wednesday, Thursday still shows Day 4.
- Week number increments after Day 7. Weeks 8, 16, 24 are deload and test weeks.
- **Deload and test week mapping** (use this unless the doc says otherwise): Day 1 Push A deload, Day 2 Pull A deload, Day 3 off, Day 4 test push, Day 5 test pull, Day 6 test flag and planche (plus a no-transition muscle-up attempt if unlocked), Day 7 off. Deload = same exercises, half the sets (round up), RIR 4, no max attempts. Abs and handstand practice stay normal. Test order inside each test day comes from the doc's Test protocol.
- **Long break:** if 14 or more days pass since the last completed session, show a banner: "Back after a break: restart at 80% of your last numbers?" One tap applies it (reps, seconds and loads scaled to 80%, rounded sensibly).
- **End of week 24:** show a summary (week 0 vs week 24 for every goal) and offer "Start next cycle", using the week 24 tests as the new baselines.
- **Week 0 baselines** are preloaded from the doc's Goals table and editable on the onboarding screen.

## 6. Progression engine

Implement each rule as a typed, tested pure function. Inputs: the plan, the current position, and the logs. Output: the exact prescription for today.

**Success rule (global):** an exercise progresses only if every set was completed as prescribed, marked clean, and the effort rating was not "Hard". Otherwise repeat the same numbers next time. This is the doc's main rule; apply it everywhere.

Rule types the doc uses (confirm each against the doc in PLAN_SPEC.md):

1. **Double progression (per-set reps array):** add 1 rep to the first set that is below the top. Example archer HSPU: [2,2,2,2] per side, then [3,2,2,2], up to [4,4,4,4]. HSPU Block 1: 5 x 6 up to 5 x 8, then add a 6th set of 6. Same mechanism for pseudo planche push-ups, dips, pull-ups, front lever raises, tuck lever rows, abs.
2. **Sequence progression:** step through a fixed list on success. Front lever clusters: 6x3s, 8x3s, 6x4s, 8x4s, and so on. Flag Day 2: 6x2s, 6x3s, 5x4s, 5x5s. Muscle-up Block 1 EMOM: 8x3, 10x3, 8x4, 10x4. 90 degree push-up: EMOM 6, 7, 8 singles, then doubles every 2 min 4x2, 5x2, then 3x3.
3. **Weekly time progression:** handstand working sets +5 s per set per week while clean. 90 degree holds +1 s per set per week up to 10 s.
4. **Percent of max:** handstand working sets = 65% of the latest max (from the weekly Day 4 max attempt), rounded to 5 s. When a new max is higher, recompute from it.
5. **Load progression:** weighted muscle-up at +5 kg: 4x2, 4x3, 4x4, then +10 kg 4x2, and so on. Weighted pull-ups: first session asks once for the starting load, then double progression. Settings holds my smallest plate increment (5, 2.5 or 1.25 kg) and the engine uses it.
6. **Total-reps method:** a target total done in as few sets as possible. Log how many sets it took. HSPU Block 2 = 50, Block 3 = 60 then 70. Muscle-up Block 2 = 30, Block 3 = 40.
7. **Level switch:** when a level reaches its top, switch exercise. One-leg front lever 4x8s up to 4x15s, then straddle 4x6s up to 4x12s. Planche: when one-leg reaches 6x5s on both legs, replace adv tuck with half-straddle and band-assisted straddle holds (starting numbers go in DECISIONS.md).
8. **Block-dependent methods:** HSPU and muscle-up change method per block exactly as the doc says, including the HSPU top set at RIR 1 in weeks 2, 4, 6 of Block 3 and the muscle-up AMRAP in week 6 of Block 3.
9. **Unlocks:** the no-transition muscle-up attempts unlock when the doc's criteria are met (3 clean explosive pull-ups to lower chest or waist AND weighted muscle-ups at +10 kg for 3 clean reps). The high-pull bar height is logged with one tap after that exercise (chest, lower chest, waist).

Progression rates the doc gives only as "from X up to Y" (for example one-leg front lever 8 s to 15 s): default to +1 s per set per successful session and record it in DECISIONS.md.

## 7. Session player (the core of the app)

Design principle: **zero taps when things go as planned, one tap when they do not.**

### Start
- Today screen shows the session name, a preview list of today's exercises with exact numbers, estimated time, and one big START button.
- The START tap does three things: unlocks audio, requests the wake lock, starts the warm-up.

### Layout (every step)
- Top: exercise name, "Set 2 of 4", small progress bar for the whole session.
- Middle, huge: the instruction. "6 REPS", "HOLD 8 s", "+5 kg  2 REPS", or the countdown.
- Below: the one-line cue. A small "How?" toggle shows the full rep standard.
- Bottom (thumb zone): at most one primary button. Secondary actions are small.

### Behavior per step type
- **Warm-up:** timed items that auto-advance with a beep. Small "Skip warm-up".
- **Hold:** rest ends, a 5 s "get in position" countdown runs, the hold starts automatically, counts down, beeps at the end, and rest starts automatically. Zero taps if clean. If I break early, tapping anywhere on the screen stops it and logs the actual seconds as not clean. Alternating legs or sides show "LEFT LEG" / "RIGHT LEG".
- **Reps:** I do the reps, tap DONE, rest starts. Default log = prescribed reps, clean. A small "Less" button opens a stepper prefilled with the prescription to log actual reps, plus a "Not clean" toggle. For the 90 degree push-up, "Not clean" ends that exercise for the day (doc rule).
- **Effort rating:** after the LAST set of a rep-based exercise, one tap: Easy / Right / Hard. It feeds the success rule. Holds do not ask.
- **EMOM:** runs on its own. Beep at every interval start, shows round n of N and reps. Zero taps. A "Missed" button logs a failed round.
- **Total reps:** shows reps remaining, huge. After each set, a stepper prefilled with my last set's reps, one tap to confirm, rest starts. Ends when the total is reached and logs sets used.
- **Max hold / AMRAP (tests and the weekly handstand max):** 3 s countdown, stopwatch counts up, tap anywhere to stop. AMRAP: enter the count with a stepper.
- **Practice / attempts:** a countdown for practice minutes, or N attempt rows with Yes/No.
- **Rest:** huge countdown, next step preview, small "+15 s" and "Skip". Beeps on the last 3 seconds. Rest durations come from the plan.
- **Finish:** summary of the session (what progressed, what repeats next time), saved automatically. "Finish early" is in a small menu and saves partial work.

### Audio and voice
- Short beeps via Web Audio (unlocked on the START tap).
- Voice cues via `speechSynthesis`, on by default: "Set 2 of 4. Archer HSPU. 2 per side." "Rest 3 minutes." "10 seconds." "Hold." "Done."
- I often train with music. Beeps and voice must mix with other audio, not stop it. Feature-detect `navigator.audioSession` and use a type that mixes or briefly ducks other audio (try `transient`, fall back to `ambient`). Verify on a real iPhone and note the result in DECISIONS.md. Settings has toggles for sound and voice.
- iOS Safari has no vibration API, so do not rely on it.

## 8. Timers must actually work

- **Timestamp-based only.** Store `startedAt` / `endsAt` as `Date.now()` values and compute remaining time on every frame (`requestAnimationFrame`, plus a 250 ms interval fallback). Never count down by decrementing a counter: iOS throttles and suspends JavaScript in the background.
- **Persist the live session** (current step, timer `endsAt`, every set result) to IndexedDB on every change. If the app is reloaded, killed or crashes mid-session, reopening it resumes the exact step with the correct remaining time. If a rest finished while the app was away, move to the next step.
- On `visibilitychange` to visible: recompute timers and re-acquire the wake lock.

## 9. Screen must stay awake

- Use the Screen Wake Lock API: `navigator.wakeLock.request('screen')` on the START tap, held for the whole session, released when the session ends or I leave the player.
- The lock is released automatically when the app goes to the background. Listen for the sentinel's `release` event and for `visibilitychange`, and request it again whenever the page becomes visible during a session.
- It works in home screen web apps on iOS 18.4 and later (earlier versions had a bug in standalone mode). Wrap requests in try/catch: the system can refuse, for example in Low Power Mode.
- **Fallback** if the API is missing or fails: the hidden muted, inline, looping video technique (the approach NoSleep.js uses), started from the same user tap. Implement it in a small module (or use nosleep.js if it stays tiny).
- Show a small indicator in the player (screen lock active or not). If both methods fail, show a one-line banner: "Screen may lock. Set Auto-Lock to Never while training."
- Requires HTTPS.

## 10. Screens and tabs

Bottom tab bar with 4 tabs. Everything big, dark theme by default (high contrast, readable at arm's length on the floor), safe-area insets respected, tap targets at least 64 px, primary actions in the bottom half.

1. **Today**
   - Position line: "Block 1 · Week 3 · Day 4: Push B".
   - A 7-dot strip for the current cycle (done, today, upcoming).
   - Training day: session preview + START.
   - Off day: "Rest day", optional 5 min handstand practice button, and the GTG checklist if GTG is on.
   - Deload or test week: a clear label ("Deload week", "Test day: push") and the test order.
   - Banners when relevant: weekly check-in due, deload recommended, long-break restart, unlock reached ("No-transition attempts unlocked").
2. **Progress**
   - One card per goal: week 0 value, latest test, best training value, target, realistic estimate (all from the doc's Goals table), and a progress bar toward the target.
   - Small SVG line chart per goal with test points over the 24 weeks.
   - Bodyweight trend from the weekly check-ins.
3. **Log**
   - Sessions list, newest first. Tap to see every set (prescribed vs done, clean or not, effort rating).
   - Edit a past set (to fix a mis-tap). The engine recomputes from the corrected log.
   - Weekly check-ins listed here too.
4. **Settings**
   - Sound, voice, audio mixing mode.
   - GTG on/off.
   - Smallest plate increment.
   - Plan position: view, and a manual "shift" control for corrections.
   - Wake lock test button.
   - Export all data to a JSON file, import from JSON, reset all data (double confirm).

### Onboarding (first launch only)
One screen: start date (default today), the week 0 test values from the doc (editable), the starting weighted pull-up load, then "Start". Nothing else.

## 11. Weekly check-in and deload triggers

- After Day 7 (or on the first open after it), Today shows a check-in with 4 quick inputs: average bodyweight (optional), nights under 6 h this week (0 to 7), worst joint pain (0 to 10), and "did it last more than 24 h?". Plus a "Planche pain at elbow or shoulder" toggle.
- Triggers from the doc: pain 3+ lasting more than 24 h, 3+ nights under 6 h, or performance down on 2 sessions in a row of the same day type (detect automatically from logs: completed below prescription twice in a row).
- If triggered: banner "Deload recommended" with [Start deload week] and [Ignore]. An early deload inserts a deload week and then resumes the same week, without advancing progression.
- Planche pain toggle: planche volume cut by 50% for 2 weeks (doc rule).

## 12. GTG (optional, off by default)

- Only when enabled in Settings, only on Day 3 and Day 6, never in deload or test weeks.
- Today shows a simple checklist: 5 rows, each "MU x3" and "HSPU x4" (or the doc's current numbers at ~40% of max), tap to tick. No timers, no alarms, no notifications.
- After 4 weeks of GTG, ask once: "Keep GTG?" Yes / No.

## 13. Data

- IndexedDB (Dexie) tables: settings, position, sessions (with set results), activeSession, tests, checkins, engineState (anything the progression needs, for example current sequence index per exercise, if you do not derive it purely from logs; deriving from logs is preferred).
- Everything is local. Note in the app: home screen web apps keep their own storage, and deleting the home screen icon deletes the data. After each test week, Today suggests "Export a backup" once.

## 14. PWA details

- Manifest: name "Calisthenics", short name "Train", display standalone, dark theme and background color, portrait.
- `apple-touch-icon` (180 px) and generated icons (simple, generic training glyph, no brand logos).
- Meta: `apple-mobile-web-app-capable`, status bar style black-translucent, `viewport-fit=cover`.
- Disable double-tap zoom and text selection in the player, prevent overscroll bounce.
- Works fully offline after first load.

## 15. Testing

- Unit tests for the engine: cycle advancing (training days, off days auto-completing at date change, no doubling, missed days, week and block rollover), each progression rule type, the success rule, deload and test weeks, early deload, long-break 80% restart, unlock criteria.
- Dev mode (`?dev=1`): timers run 10x faster, and a panel to jump to any block/week/day and to fake dates. Hidden in normal use.
- Write `IPHONE_CHECKLIST.md` with manual tests I run on the device:
  - Add to home screen, launch standalone.
  - Start a session, leave the phone untouched for 3 minutes: the screen stays on.
  - Lock the phone mid-rest, unlock after 30 s: the timer shows the right time.
  - Kill the app mid-session, reopen: it resumes the same step.
  - Music playing in another app: beeps and voice mix in, music keeps playing.
  - Airplane mode: everything works.
  - Export, reset, import: data comes back.

## 16. Out of scope

Accounts, login, backend, sync, push notifications, analytics, social features, an exercise library, a plan editor, other users' plans. If something seems useful but is not in this prompt or the doc, list it at the end of DECISIONS.md as a suggestion instead of building it.

## 17. Acceptance criteria

- I open the app, it shows exactly today's session with exact numbers, and I can do the whole session with START plus one tap per rep set.
- Every rest and hold is timed, cued by sound and voice, and correct even after locking the phone or reloading.
- The screen stays awake for the whole session on iOS 18.4+ when launched from the home screen.
- Every set is logged, and the next session's numbers follow the doc's progression rules.
- Deload weeks, test days, check-ins and unlocks appear on their own at the right time.
- No account, no server, works offline.
